# Terraform AKP Provider Version 0.15 Upgrade Guide

Version 0.15.0 of the AKP provider for Terraform adds support for managing Argo CD managed secrets through the `akp_instance` resource and inspecting their non-sensitive metadata through the `akp_instance` data source. This guide covers the upgrade from version 0.14.x to version 0.15.0.

## Terraform CLI Requirement

Version 0.15.0 requires Terraform CLI 1.11.0 or later. Managed secret data uses Terraform's write-only attribute support so secret values can be sent to Akuity without being stored in Terraform state or plan output. Write-only attributes are not supported by earlier Terraform CLI versions.

Check the installed version before upgrading the provider:

```shell
terraform version
```

Set the minimum version in your Terraform configuration:

```terraform
terraform {
  required_version = ">= 1.11.0"
}
```

Upgrade Terraform CLI before upgrading the provider if the installed version is older than 1.11.0.

## Provider Version Configuration

→ Before upgrading to version 0.15.0, upgrade to version 0.14.1 of the provider and ensure that your environment successfully runs [`terraform plan`](https://www.terraform.io/docs/commands/plan.html). You should not see changes you do not expect or deprecation notices. Also, back up your `.tf` and `.tfstate` files before starting the upgrade process.

Use [version constraints when configuring Terraform providers](https://www.terraform.io/docs/configuration/providers.html#provider-versions). If you are following that recommendation, update the version constraint and run [`terraform init -upgrade`](https://www.terraform.io/docs/commands/init.html) to download the new version.

For example, given this previous configuration:

```terraform
terraform {
  required_providers {
    akp = {
      source  = "akuity/akp"
      version = "~> 0.14.0"
    }
  }
}
```

Update the Terraform CLI requirement and provider version:

```terraform
terraform {
  required_version = ">= 1.11.0"

  required_providers {
    akp = {
      source  = "akuity/akp"
      version = "~> 0.15.0"
    }
  }
}
```

## Managed Secrets

Version 0.15.0 adds the `managed_secrets` map to the `akp_instance` resource. Each entry creates or updates an Argo CD managed secret in the Akuity control plane and can target managed clusters by name or label selector.

```terraform
variable "deployment_token" {
  type      = string
  sensitive = true
}

resource "akp_instance" "example" {
  name = "argocd"

  managed_secrets = {
    deployment-token = {
      labels = {
        environment = "production"
      }
      cluster_selector = "environment=production"
      data = {
        token = var.deployment_token
      }
      data_version = "1"
    }
  }
}
```

The supported fields are:

- `labels` adds labels to the managed secret.
- `allowed_clusters` lists cluster names that receive the secret. Use `ALL` to target every cluster. When set, it takes precedence over `cluster_selector`.
- `cluster_selector` targets clusters using a Kubernetes label selector.
- `data` contains the secret values. It is write-only and is never stored in Terraform state or returned by the API. Omitting `data` keeps the existing secret data unchanged. Setting `data` to an empty map (together with a new `data_version`) removes every key from the secret.
- `data_version` is a version marker for `data`. Change it whenever a secret value changes so Terraform detects the update and sends the new data.

Removing an entry from `managed_secrets` deletes that secret. Managed secrets are never adopted: creating an entry whose name matches a secret that already exists (created through the Akuity UI, API, or declarative CLI) fails with an "already exists" error — delete the existing secret or choose a different name. Secrets that are not listed in `managed_secrets` are never modified or deleted; they remain visible to the data source. Secrets created by this provider carry the `akuity.io/managed-secret-owner: terraform` annotation. A retried or interrupted apply, or a configuration rebuilt from a fresh state, recognizes those Terraform-created secrets instead of reporting a conflict; secrets created outside Terraform are never adopted. During that recovery the `data` rules above still apply: set `data` replaces the values, an empty map removes every key, and omitted `data` keeps the existing values. Managing one instance from more than one Terraform configuration is not supported.

The `akp_instance` data source exposes managed secret labels, cluster targeting, and secret key names. It never exposes secret values.

```terraform
data "akp_instance" "example" {
  name = akp_instance.example.name
}

output "managed_secret_keys" {
  value = data.akp_instance.example.managed_secrets["deployment-token"].secret_keys
}
```

## Apply the Change

After upgrading Terraform CLI and updating the provider version, run:

```shell
terraform init -upgrade
terraform plan
```

Managed secret support is additive. Existing `akp_instance` configurations that do not configure `managed_secrets` should not produce managed-secret changes after the upgrade. Review the plan before applying it.
