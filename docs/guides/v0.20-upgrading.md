# Terraform AKP Provider Version 0.20 Upgrade Guide

Version 0.20.0 adds agent federation to the `akp_cluster` and `akp_kargo_agent` resources and data sources. Existing configurations need no changes. If you are upgrading from an older provider version, also follow the [v0.19 upgrade guide](v0.19-upgrading.md).

## Platform Requirement

Self-hosted Akuity Platform: `spec.data.federation` needs a platform release that accepts federation in declarative apply. Older platforms ignore the block, so federation is not enabled even though the plan shows it.

## Agent Federation

Set `spec.data.federation` to let the agent authenticate to the control plane with service account tokens issued by its own cluster instead of a static token:

```terraform
resource "akp_cluster" "example" {
  # ...
  spec = {
    data = {
      size = "small"
      federation = {
        issuer   = "https://oidc.eks.us-west-2.amazonaws.com/id/EXAMPLE"
        jwks_url = "https://oidc.eks.us-west-2.amazonaws.com/id/EXAMPLE/keys"
      }
    }
  }
}
```

Give either `jwks` (the key set as a JSON string) or `jwks_url`; with neither, keys are discovered from the issuer. `akp_kargo_agent` also takes `promotion_service_accounts`. The organization needs the agent federation feature.

Enabling federation rotates the agent credentials once. If auto-upgrade is disabled for the cluster or Kargo agent, re-apply its agent manifests afterwards so the agent picks up the federated configuration and rotated credentials. Federation is one-way: the settings cannot be changed once enabled, and removing the block from the configuration keeps them.
