# Terraform AKP Provider Version 0.19 Upgrade Guide

Version 0.19.0 removes the deprecated `assistant_extension_enabled` attribute, makes `repo_credential_secrets` and `repo_template_credential_secrets` follow your configuration when a key or an entry is removed, and reads only the objects Terraform manages. This guide covers the upgrade from version 0.18.x to version 0.19.0.

Upgrading does not require resource renames. Remove `assistant_extension_enabled` from your configuration before upgrading, as described in [Legacy AI Assistant Attribute](#legacy-ai-assistant-attribute). The only state change, dropping that attribute, is migrated automatically. Terraform CLI 1.11.0 or later remains required. If you are upgrading from an older provider version, also follow the [v0.18 upgrade guide](v0.18-upgrading.md).

Three Akuity Platform changes affect existing configurations on every provider version, so check them even if you stay on 0.18.x: the [legacy AI Assistant attribute](#legacy-ai-assistant-attribute), [repository credential secrets](#repository-credential-secrets) and [kustomize versions](#kustomize-versions).

## Platform Requirement

Self-hosted Akuity Platform: upgrade the platform to a release later than v0.34.1 before upgrading the provider. Version 0.19.0 sends a field on every `akp_instance` apply that older platforms do not know, and they reject the request.

## Provider Version Configuration

Before upgrading, run `terraform plan` with your current provider version and resolve any unexpected changes. Back up your configuration and state, then update the provider version constraint:

```terraform
terraform {
  required_version = ">= 1.11.0"

  required_providers {
    akp = {
      source  = "akuity/akp"
      version = "~> 0.19.0"
    }
  }
}
```

Run `terraform init -upgrade` to install the new provider, then review `terraform plan`.

## Legacy AI Assistant Attribute

The deprecated `argocd.spec.instance_spec.assistant_extension_enabled` attribute is removed from the `akp_instance` resource and data source. The legacy AI Assistant was replaced by AI Agents, and the attribute no longer enabled a feature.

Configurations that still set the attribute fail to plan with version 0.19. Remove assignments to `true`, `false` or `null`, and remove expressions that read the attribute from the resource or the data source. For example, remove this line from `argocd.spec.instance_spec`:

```terraform
assistant_extension_enabled = true
```

The provider drops the attribute when Terraform upgrades the existing state. You do not need to edit state, re-import an instance, or recreate an instance. Other instance settings remain unchanged.

### If You Stay on an Older Provider

Remove the attribute from your configuration even if you keep your current provider version. The Akuity Platform still accepts the field in requests, so the default `false` that older providers send keeps working, but it ignores the value and no longer returns the field. Some older providers, such as `v0.9.21`, read the missing field as `false` during refresh and after apply. With those versions, a configuration that explicitly sets `true` shows repeated plan differences or fails with an inconsistent-result error after apply. Version 0.18 keeps the value already in state, so it does not show this drift.

With the attribute omitted, those older providers accept the refreshed `false` value because the attribute is computed. You do not need to edit state or recreate the instance.

## Repository Credential Secrets

Previously, removing a key from an entry of `repo_credential_secrets` or `repo_template_credential_secrets` left the key in the secret, and removing an entry left the whole secret in Argo CD.

The Akuity Platform now replaces each secret's data with the values in its entry, on every provider version:

- A key that is no longer in the entry is removed from the secret. Setting the key to an empty string is no longer needed.
- A key that was added to the secret outside Terraform, for example in the Argo CD UI, is removed on the next apply of that entry. Add the key to your configuration if you want to keep it.
- Labels and annotations already on the secret are kept.

Version 0.19 also deletes a secret when its entry is removed from your configuration:

- Only secrets tracked in this resource's state are deleted. Secrets that Terraform never managed are left alone.
- Moving an entry between `repo_credential_secrets` and `repo_template_credential_secrets` does not delete the secret.

Secrets whose entries you removed with an earlier provider version are no longer in state, so version 0.19 does not delete them. Delete them in the Argo CD UI or with the Argo CD CLI.

Review `terraform plan` if you relied on keys or secrets staying in place after they were removed from configuration.

## Kustomize Versions

The Akuity Platform now rejects a `manifest_generation.kustomize` `default_version` or `additional_versions` entry that no Argo CD release bundles. This applies to every provider version. Such a version was never installed, so the pin had no effect before:

```text
unsupported kustomize version "v5.7.1": no Argo CD release bundles it
```

The check covers the whole instance spec, so an instance that already stores an unsupported version has every later `terraform apply` rejected until the version is fixed. Use a version that an Argo CD release bundles, as offered in the instance's kustomize settings in the Akuity Portal:

```terraform
manifest_generation = {
  kustomize = {
    default_version     = "v5.8.1"
    additional_versions = ["v5.7.0", "v5.8.0"]
  }
}
```

## Reading Only Managed Objects

`akp_instance` and `akp_kargo_instance` reads now ask the platform only for the objects in `argocd_resources` or `kargo_resources`, instead of exporting every Application, ApplicationSet, AppProject, or Kargo object on the instance. Plan and refresh get much cheaper on large instances, and no configuration change is needed. The provider still does a full export and filters it itself when the list of objects would make the request URL longer than 4 KiB, and against platforms that predate the filter.

The `akp_instance` and `akp_kargo_instance` data sources take an optional `resource_filter` that limits `argocd_resources` or `kargo_resources` to the named objects. Each entry is written like a key of that map, `<apiVersion>/<kind>/<namespace>/<name>`:

```terraform
data "akp_instance" "team_a" {
  name            = "example"
  resource_filter = ["argoproj.io/v1alpha1/AppProject//team-a"]
}
```

Without `resource_filter` the data sources behave as before, and an empty set gives an empty map. An invalid entry, or a set that takes more than 4 KiB in the request URL, fails the read instead of falling back to a full export. See the [`akp_instance`](../data-sources/instance.md) and [`akp_kargo_instance`](../data-sources/kargo_instance.md) data sources for the matching rules.

## Apply the Change

After updating the provider version and your configuration, run:

```shell
terraform init -upgrade
terraform plan
```

Review the plan before applying it. Removing a repository credential entry now deletes its secret on apply.
