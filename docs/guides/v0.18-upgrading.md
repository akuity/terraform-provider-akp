# Terraform AKP Provider Version 0.18 Upgrade Guide

Version 0.18.0 adds admission policies for Argo CD and Kargo instances, ApplicationSet SCM generator settings, and ApplicationSets in any namespace. The new settings are optional, and upgrading from 0.17.x does not require resource renames or state migration. Terraform CLI 1.11.0 or later remains required. If you are upgrading from an older provider version, also follow the [v0.17 upgrade guide](v0.17-upgrading.md).

Two Akuity Platform changes affect existing configurations on every provider version, so check them even if you stay on 0.17.x: [ApplicationSet plugin tokens](#applicationset-plugin-tokens) and [tokenRef strict mode](#tokenref-strict-mode).

## Provider Version Configuration

Back up your configuration and state, then update the provider version constraint:

```terraform
terraform {
  required_version = ">= 1.11.0"

  required_providers {
    akp = {
      source  = "akuity/akp"
      version = "~> 0.18.0"
    }
  }
}
```

Run `terraform init -upgrade` to install the new provider, then review `terraform plan`.

## Admission Policies

`argocd_resources` on `akp_instance` and `kargo_resources` on `akp_kargo_instance` now accept `ValidatingAdmissionPolicy` and `ValidatingAdmissionPolicyBinding` manifests with apiVersion `admissionregistration.k8s.io/v1`. Argo CD policies can match `applications` and `applicationsets` in `argoproj.io`. Kargo policies can match `stages` in `kargo.akuity.io`.

If you load `argocd_resources` from a directory of manifests, as in the exhaustive example of the [`akp_instance` resource](../resources/instance.md), add the policy and its binding as a new file, e.g. `argocd-manifests/admission-policy.yaml`:

```yaml
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingAdmissionPolicy
metadata:
  name: require-autosync-selfheal
spec:
  failurePolicy: Fail
  matchConstraints:
    resourceRules:
      - apiGroups: ["argoproj.io"]
        apiVersions: ["v1alpha1"]
        operations: ["CREATE", "UPDATE"]
        resources: ["applications"]
  matchConditions:
    - name: spec-changed
      expression: "oldObject == null || object.spec != oldObject.spec"
  validations:
    - expression: >-
        has(object.spec.syncPolicy) && has(object.spec.syncPolicy.automated)
          && (!has(object.spec.syncPolicy.automated.enabled)
            || object.spec.syncPolicy.automated.enabled != false)
          && has(object.spec.syncPolicy.automated.selfHeal) && object.spec.syncPolicy.automated.selfHeal
      message: all Applications must use automated sync with selfHeal enabled
---
apiVersion: admissionregistration.k8s.io/v1
kind: ValidatingAdmissionPolicyBinding
metadata:
  name: require-autosync-selfheal
spec:
  policyName: require-autosync-selfheal
  validationActions: ["Deny"]
```

This policy rejects `automated.enabled: false`, even when `selfHeal` is `true`. An omitted or `null` value for `enabled` is treated as enabled, matching [Argo CD's automated sync behavior](https://argo-cd.readthedocs.io/en/stable/user-guide/auto_sync/).

The `spec-changed` match condition skips updates that do not change `spec`, so Argo CD can still update the status of existing Applications.

Once your configuration declares any admission policy or binding, Terraform manages every admission policy on that instance:

- Policies that are not in your configuration, including ones added in the Akuity Portal, are deleted on the next apply.
- Removing the last policy from your configuration deletes all policies on the instance.

If your configuration never declares one, Terraform leaves the instance's policies alone. Before you add the first policy, copy any existing policies you want to keep into your configuration. You can find them in the instance settings in the Akuity Portal, or in `argocd_resources` and `kargo_resources` of the `akp_instance` and `akp_kargo_instance` data sources.

## ApplicationSet SCM Generator Settings

`appset_scm_config` in `argocd.spec.instance_spec` controls the ApplicationSet SCM Provider and Pull Request generators:

- `scm_providers_disabled` turns both generators off. It defaults to `false`.
- `allowed_scm_providers` lists the custom SCM API URLs that the generators may call. Each URL must match exactly, including the protocol. It defaults to `[]`, which allows any URL.
- `token_ref_strict_mode_disabled` turns [tokenRef strict mode](#tokenref-strict-mode) off. It defaults to `false`.

For example, to limit custom SCM API URLs to one Git server, add this inside `instance_spec`:

```terraform
appset_scm_config = {
  scm_providers_disabled         = false
  allowed_scm_providers          = ["https://git.example.com/"]
  token_ref_strict_mode_disabled = false
}
```

If you leave `appset_scm_config` out, the instance keeps its current settings. To reset a field, set it back to its default value.

### tokenRef Strict Mode

The Akuity Platform now turns tokenRef strict mode on by default, for every provider version. In strict mode, a `tokenRef` in an SCM Provider or Pull Request generator can only read a Secret with the `argocd.argoproj.io/secret-type: scm-creds` label.

The `application-set-secret` Secret that `application_set_secret` manages already has this label, so keep generator tokens there:

```terraform
application_set_secret = {
  "github-token" = var.github_token
}
```

Then reference the key from the generator:

```yaml
tokenRef:
  secretName: application-set-secret
  key: github-token
```

If a `tokenRef` reads another Secret, add the label to that Secret, or set `token_ref_strict_mode_disabled = true` in `appset_scm_config`.

## ApplicationSets in Any Namespace

Set `appset_in_any_namespace_enabled = true` to let the ApplicationSet controller reconcile ApplicationSets in every namespace except `kube-system`. It requires Applications in any namespace, and SCM generators that are either disabled or limited by an allow list. Add this inside `instance_spec`:

```terraform
app_in_any_namespace_config = {
  enabled = true
}
appset_scm_config = {
  scm_providers_disabled         = false
  allowed_scm_providers          = ["https://git.example.com/"]
  token_ref_strict_mode_disabled = false
}
appset_in_any_namespace_enabled = true
```

If you leave `appset_in_any_namespace_enabled` out, the instance keeps its current setting. Set it to `false` to turn it off.

## ApplicationSet Plugin Tokens

The Akuity Platform now requires `appset_plugins` tokens to reference a secret key, for every provider version. Argo CD never resolved raw tokens, so a plugin with a raw token already failed at runtime. Now `terraform apply` fails instead, with an error that says the token must reference a secret key.

Move the token into `application_set_secret` and reference it as `$application-set-secret:<key>`. Merge the following into your `akp_instance` resource:

```terraform
argocd = {
  spec = {
    instance_spec = {
      appset_plugins = [
        {
          name            = "plugin-test"
          token           = "$application-set-secret:plugin-token"
          base_url        = "https://example.com"
          request_timeout = 30
        }
      ]
    }
  }
}
application_set_secret = {
  "plugin-token" = var.plugin_token
}
```

To use a key in `argocd-secret`, which `argocd_secret` manages, write `$<key>` instead.

## Apply the Change

After updating the provider version and any settings, run:

```shell
terraform init -upgrade
terraform plan
```

Review the plan before applying it, especially when you add the first admission policy to an instance.
