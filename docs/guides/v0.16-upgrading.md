# Terraform AKP Provider Version 0.16 Upgrade Guide

Version 0.16.0 adds MCP access configuration, default agent sizing and autoscaling limits, ApplicationSet git file globbing configuration, and Git credential access for Config Management Plugins. This guide covers the upgrade from version 0.15.x to version 0.16.0.

The new settings are optional, and upgrading from 0.15.x does not require resource renames or state migration. Terraform CLI 1.11.0 or later remains required for write-only managed secret attributes. If you are upgrading from an older provider version, also follow the [v0.15 upgrade guide](v0.15-upgrading.md).

## Provider Version Configuration

Before upgrading, run `terraform plan` with your current provider version and resolve any unexpected changes. Back up your configuration and state, then update the provider version constraint:

```terraform
terraform {
  required_version = ">= 1.11.0"

  required_providers {
    akp = {
      source  = "akuity/akp"
      version = "~> 0.16.0"
    }
  }
}
```

Run `terraform init -upgrade` to install the new provider, then review `terraform plan` before enabling the new features.

## MCP Access

The `akp_instance` and `akp_kargo_instance` resources support `mcp_server.enabled` at these paths:

| Resource | Attribute path |
| --- | --- |
| `akp_instance` | `argocd.spec.instance_spec.mcp_server.enabled` |
| `akp_kargo_instance` | `kargo.spec.kargo_instance_spec.mcp_server.enabled` |

Add this configuration inside the existing `instance_spec` or `kargo_instance_spec` object:

```terraform
mcp_server = {
  enabled = true
}
```

Enabling it requires the organization's MCP server feature. It allows MCP access through the instance's own `/mcp` endpoint and instance actions through the organization's platform MCP endpoint. It does not enable the organization's platform endpoint itself.

Set `enabled = false` to disable MCP access for the instance. Omitting the optional configuration does not explicitly disable an existing setting. The corresponding data sources expose the MCP configuration, and changes to an explicitly configured value are detected during refresh.

## Default Agent Sizing

Instance customization defaults now accept `size` and `autoscaler_config`. They apply to new clusters or agents that do not specify their own size; changing a default does not resize existing agents. Akuity-managed Kargo agents do not inherit these size defaults.

The supported sizes are `small`, `medium`, `large`, and `auto`. For a custom resource allocation, use `size = "large"` with resource patches in the defaults' `kustomization`; `custom` is not an accepted size value.

### Argo CD

Merge the following into `argocd.spec.instance_spec.cluster_customization_defaults` on an existing `akp_instance` resource, preserving any other customization defaults:

```terraform
size = "auto"
autoscaler_config = {
  application_controller = {
    resource_minimum = { cpu = "500m", memory = "1Gi" }
    resource_maximum = { cpu = "2", memory = "4Gi" }
  }
  repo_server = {
    resource_minimum = { cpu = "250m", memory = "512Mi" }
    resource_maximum = { cpu = "1", memory = "2Gi" }
    replicas_minimum = 1
    replicas_maximum = 3
  }
}
```

### Kargo

Merge the following into `kargo.spec.kargo_instance_spec.agent_customization_defaults` on an existing `akp_kargo_instance` resource:

```terraform
size = "auto"
autoscaler_config = {
  kargo_controller = {
    resource_minimum = { cpu = "500m", mem = "1Gi" }
    resource_maximum = { cpu = "2", mem = "4Gi" }
  }
}
```

Argo CD uses `memory` for these limits, while Kargo uses `mem`. Configure `autoscaler_config` with `size = "auto"`, and remove it when selecting a fixed size. The provider rejects scaling limits paired with a fixed or unset size during planning, since the control plane would drop those limits.

The provider preserves your configured spelling when the API returns an equivalent resource quantity, e.g., `4Gi` and `4.00Gi`, so normalization does not cause an inconsistent-result error. Different quantities still appear as drift. Both instance data sources expose the sizing defaults.

## ApplicationSet Git File Globbing

The `akp_instance` resource and data source now expose `argocd.spec.instance_spec.appset_new_git_file_globbing_enabled`. To opt in, add this attribute inside the existing `instance_spec` object:

```terraform
appset_new_git_file_globbing_enabled = true
```

With the new globbing behavior, `*` matches a single path segment and `**` matches across directories. Existing patterns that relied on `*` matching nested directories may stop selecting files. Review the git file generators in your ApplicationSets before enabling this setting, and use `**` where recursive matching is intended. Upgrading the provider alone does not opt in to the new behavior.

## Config Management Plugin Git Credentials

Config Management Plugins now support `provide_git_creds` under `config_management_plugins["<plugin-name>"].spec` on `akp_instance`. Add `provide_git_creds = true` to an existing plugin's `spec` to let it obtain the Application source repository's Git credentials from the repo-server during manifest generation.

The setting defaults to `false`. Enable it only for trusted plugins, since the plugin can authenticate to that repository as Argo CD. Keep the plugin's existing image, commands, and other settings when adding the attribute. The [Config Management Plugin guide](managing-cmps.md) covers the complete plugin configuration.

## Kargo Agent Imports

This release fixes workspace resolution when importing Kargo agents with API-key authentication. The provider resolves the parent instance's actual workspace instead of potentially selecting the first workspace returned. Existing resources do not need to be re-imported, but review any workspace correction reported by `terraform plan` for previously imported agents.

## Apply the Change

After updating the provider version and any feature settings, run:

```shell
terraform init -upgrade
terraform plan
```

Review the plan before applying it. In particular, confirm MCP access changes and agent sizing defaults match your intent, and review ApplicationSet file patterns before enabling the new globbing behavior.
